# V2 — Minimal oracle scope and bit-bound correction, before code

2026-10-17. The eight criteria remain unchanged. No resource/model campaign.

The last paragraph of V1's bit discussion needs an explicit numerator bound:
a denominator bound alone does not bound arbitrarily large unnormalized
weights. For the stated O(n*(b+log V)) numerator/denominator bit bound, let b
bound BOTH the numerator bit length and denominator power of each nonnegative
dyadic slot weight. Alternatively normalized weights in[0,1] satisfy the
needed numerator bound automatically. V1 stays literal in its commit; the
correction is recorded before prototype execution. No measured result changes.

First implement ONLY the normalizer/index for the declared fixed band[1,100),
with two order headers. This is a two-order relation oracle, not a claim of
general positive-band/native-decoder support. Original finite token supports,
aliases, fixed slots and empty emitted bytes are allowed. Compute a safe source
byte bound from all positive-weight slots, and refuse a supplied smaller L.
The source here has a fixed number of token slots; EOT/PAD/native adapters
remain pending and cannot inherit old tests from other attempts.

Use independent standard JSON parsing with Decimal/Fraction to enumerate
small source tapes and group their true numerical values. Check normalization
path count1 for every admitted numeral and0 otherwise, including actual sign
regressions/trailing zeros. Compare exact semantic mass, CDF at atom boundaries,
strict/inclusive comparisons, quantiles at exact cumulative boundaries,
original-ID aliases/fixed slots and zero-support refusal. A one-slot four-word
illustration may verify the stated35.6/53.4 subjective risks; it is not a
neural performance or prediction-accuracy result. No favorable corpus selection.

The tiny oracle can check the mathematical relation. It cannot establish an
own speed advantage, academic priority or real usefulness. Complete cached
register/prefix and generic filtered-WFST controls remain required BEFORE any
cost/model campaign; they may match the method.

Additional primary reading: Doleschal/Kimelfeld/Martens, LMCS19(3), Section3.3.1
and Theorem5.3/proof were read directly. Its CWidth result concerns numerical
weight functions on a constant number of spans of a FIXED document and
unambiguous extraction tuples. It is not automatically the distributional
quantile of a probability-weighted numeral source. General weighted-automata
quantile statements must retain those distinctions; this reading neither
establishes A60 priority nor a separation from the complete framework.
