# A67 — Effective local envelopes for a value-only Bernoulli factory

2026-10-17. Written BEFORE code, coefficient tests or sampling. A new,
justified theoretical/software TCC scope; not another negative-covariance
coupler or a reopening of A34's failed neural screens. No model campaign.

1. **Real operation.** Given sampling-only access to Bernoulli(p), unknown p,
   and a user-defined probability link f, return an EXACT Bernoulli(f(p)).
   Exact-simulation/Monte Carlo libraries already expose this operation. A
   bounded smooth calibration spline is an admissible input, not a claimed
   deployed dLLM application. A p-coin could classify a complete structured
   decoder output, but that interface/class cost is not validated here.
   The user allows a justified different TCC scope; this investigates an
   implementable numerical probability primitive on its own merits.
2. **Candidate difference.** For C2 functions with Lipschitz second derivative,
   supplied range/curvature bounds, give explicit coefficient consistency,
   positive-mixture weights and expected work using ONLY f-values. A coefficient
   uses three values on a dyadic grid, without a derivative oracle. Bernstein
   correction, finite differences, hypergeometric elevation, positive-series
   factories and binary splitting are CLASSICAL. The possible own contribution
   is this complete effective construction/locality/cost specialization, not
   the existence of finite-mean factories for smooth functions. Specific
   priority and sufficient significance remain OPEN.
3. **Why choose it.** The written candidate makes all constants computable,
   has finite expected input flips AND a stated route to finite expected bit
   work, rather than only a tail big-O. The initial coefficient needs three
   function evaluations; the ordinary order-two Boolean-sum coefficient
   generally depends on the entire n+1-point grid. This is a restricted cold
   coefficient-query comparison, not a lower bound on all factory algorithms.
   Compare raw Nacu--Peres envelopes, derivative-corrected local coefficients,
   Lorentz/HNP, Sevy/Boolean sums, analytic/rational factories where applicable,
   and equally cached/binary-split implementations. No current timing victory.
4. **Proof before code.** `work/theory-v1.md` gives the explicit stencils,
   coefficient box/elevation inequalities, exact positive mixture, input cost,
   and arithmetic requirements. The nonanalytic cubic-spline example is an
   application of the theorem, not a favorable benchmark or model result.
5. **First validation only.** `work/protocol-v1.json` fixes small independent
   rational coefficient/finite-difference/elevation/mixture checks and a
   polynomial control. No random-sampling success frequencies can establish
   exactness. No full sampler or broad performance campaign before correctness,
   closest-source comparison and full bit-work implementation survive audit.
6. **Full cost.** Count supplied-function preparation/evaluations, every p-coin,
   auxiliary exact RNG, coefficient/elevation arithmetic, common denominators,
   binomials, output and memory. The finite-bit theorem requires a specified
   common-denominator/value-complexity model and fast integer multiplication;
   naive Fraction loops or Python's asymptotic multiplication must NOT silently
   inherit its expected-runtime conclusion. A fixed cap changes the law or
   adds FAIL; do not call conditional successes exact without a separate proof.
7. **Fatal objections.** A prior quasi-interpolant may already give the same
   effective coefficient bounds. A derivative or closed form may be readily
   available and cheaper. Cold locality can disappear after caching; source
   flips may dominate and the explicit initial degree may be conservative.
   HNP already has the smooth finite-mean capability. A direct classical
   implementation can invalidate an own substantial advantage. No artificial
   restriction excludes these controls.
8. **Article gap.** Audit the exact closest coefficient construction and
   quantitative constants, validate the proof/software, implement full bit
   costs, and establish a useful comparative consequence for actual library
   users. No human review, priority, publication/admission or completed goal
   is claimed. Correctness alone will not close T8809/T8903.
