## Operation and refinement of the eight criteria

1. The eventual consumer requests TWO executable arithmetic JSON programs for
   later execution/selection. A recursive GLC restricts expression syntax,
   not answers. The native EPIC generator remains unchanged. The prefix oracle
   stops when the contiguous accepted bytes determine ANY root operator, or
   when the original generator ends/refuses first. Its class is mul/div versus
   add/sub/unknown, fixed before heads. Root failure is NOT filtered away.
2. The proposed distinction remains A34's sharp regular sample-only frontier,
   not arithmetic program synthesis, prefix sampling, antithetics or the
   known sequential-estimation principles. Priority/significance stay OPEN.
3. A real cheap prefix could avoid completing discarded auxiliary programs.
   Whether this class signals final correctness is UNKNOWN. This diagnostic
   does not measure accuracy or compare the proposed pair against competitors.
4. A34's construction applies to any iid payload, including a whole stopped
   native prefix with its control locals/RNG. The full-cost corollary applies
   ONLY if its costs and class signal hold. Unlike the first-event draft,
   this prefix CAN require several model forwards: charge every one.
5. Run all eight questions, 32 iid seeded prefixes each, and continue the
   literal first prefix once per question. No resampling for good status.
   Record all failures and partial records. The fixed RESOURCE screen is:
   at least three prefixes of EACH binary class, at least two NEW subsequent
   forwards for the first retained continuation, and mean prefix cost <= that
   continuation's cost in BOTH wall and CPU units. At least two of eight
   questions must meet all conditions before a larger quality experiment.
   This is a necessary feasibility screen, not a scientific utility gate.
6. Record model load separately; charge grammar, prompt, copies, RNG, native
   rejection/parsing, classification, generator cleanup, cache/transfers and
   ALL new forwards. The shared first head is timed explicitly. Publish mean
   cold prefix cost AND mean after removing that ONE common first-forward
   cost. No heavy checks/model work concurrently. No inference about latency
   of a competitive complete batch: only the initial head is memoized here.
7. The strongest objections are late root commitment, negligible class
   variation, poor semantic signal, numeric-answer shortcuts, probability-aware
   controls and more-output iid. If the resource screen fails, preserve it
   and stop this application before buying a large quality campaign. A pass
   merely licenses that investigation, with competent full EPIC caches,
   deterministic/mixed/raw-probability controls and equal complete costs.
8. Missing: nearest-prior audit, independent mathematics review, meaningful
   semantic improvement against all controls, then independent confirmation
   and article. Neither a fake replay nor this small diagnostic fills them.

## Fidelity and resource boundaries

CPU threads4, pinned LLaDA8B-Instruct NF4/bfloat16 and pinned EPIC, temperature1,
128 positions/16 steps, native regular-cover min2/exact and DFA-free checker
enabled identically. Seeded generators retain Python/NumPy/CPU/CUDA tapes.
This is the native generator, NOT its separate autocomplete recovery wrapper;
any competitive full-output comparison must include that recovery identically.
All draws can be completed or failed; no support truncation/top-K is added.

The supplied prefix `{"op":"` is fixed, the rest freely generated. Grammar
construction calls native `to_normal_form` twice for ALL paths: this primes
the unchanged Rust normal-form cache to avoid the recursive OnceCell deadlock
found in the batch fake fixture. This is a common setup workaround, not an
advantage over a deliberately defective comparator. The first-cache-clone
must remain immutable. Keep at most the first suspended generator and one
current auxiliary live in this diagnostic; close every auxiliary before the
next. No pool of twelve GPU-logit payloads.

Untrusted execution has explicit budgets: 65,536 input characters, 1,024 AST
nodes, depth64, numeric literal256 characters/exponent magnitude1024 and
intermediate numerator/denominator16,384 bits. A refusal is reported, not a
changed grammar or silently renormalized model law. Per-question forward guard
1,024 and prompt-token guard1,024 are failures, not infeasibility proofs.

Source/config/inputs are checked byte-for-byte against a complete commit
before loading weights. Outputs refuse overwrites and flush every row. No
independent test labels or human review are accessed or invented.
