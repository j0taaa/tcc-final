# A68 — Sample a Bernstein increment without evaluating its full coefficient

2026-10-17. Written BEFORE new implementation or scientific execution. A67's
generic locality claim stays withdrawn. This adopts its strongest CLASSICAL
n-1 control as the starting operator, not as an own approximation invention.

1. **Operation/use.** An exact-simulation library accepts an unknown-p coin
   and a supplied smooth probability link f, and returns Bernoulli(f(p)).
   Existing BernoulliFactory.jl and general-factory interfaces identify this
   numerical operation independently of our benchmark. The narrower operation
   here is sampling each normalized Bernstein increment using a value callback
   for f. No dLLM application is established; this is the separately authorized
   numerical-library TCC scope. A decoder-verifier p-coin is only a possible
   interface, not measured use or an assumption of cheap model forwards.
2. **Own candidate.** Derive an explicit f-INDEPENDENT hypergeometric residual
   envelope whose known mass fits inside the positive-mixture increment. It
   permits a deterministic cap of NINE f-value calls for a complete output,
   irrespective of degree/curvature metadata. Finite differences, quadratic
   quasi-interpolation, control variates, importance sampling, positive series,
   rejection and binary splitting are CLASSICAL. Candidate significance is
   the complete certified constant-query specialization, not those principles.
   Priority and adequate publication significance are still OPEN.
3. **Comparative consequence.** At the SAME enlarged envelope/count law, the
   output law is exactly that of dense coefficient evaluation, with <=9 value
   calls instead of a growing grid. A written exact-coefficient oracle lower
   bound is restricted to EVALUATING that coefficient, not all competing
   samplers. The tighter H-envelope classical factory uses fewer input coins;
   retain it, direct polynomial/analytic factories, caching, lazy bounds and
   generic signed-estimation/importance controls. No full-cost victory yet.
4. **Proof first.** theory-v1.md writes residual identity, pointwise envelope,
   mass bound9H/(8m^1.5), safe Bernoulli mixture and conditional/unconditional
   laws. At most six setup calls plus three on an optional branch. The larger
   envelope2H increases the written input mean to n0+24H/sqrt(n0); explicitly
   charge that cost. New proof is written, not Lean/human review/software proof.
5. **Bounded initial validation.** protocol-v1.json fixes independent rational
   checks of EVERY residual on the original six functions and two degrees,
   both stencil directions, exact mixture laws and callback counts. No random
   frequencies can prove exactness. No full production sampler, timing/model
   campaign before the resource/priority comparison justifies one.
6. **Full costs.** Computing/sampling the envelope still costs arithmetic and
   auxiliary bits. Known rational weights have a theoretical fast-arithmetic
   O(m polylog m) route; naive Fraction tables do not inherit it. Count all
   source coins, callback bit costs, hypergeometric preparation and unranking,
   auxiliary RNG, output and memory. A low query cap is not a speed claim.
7. **Fatal objections.** The explicit construction may be a minor or previously
   used specialization of classical importance/control-variate methods. Cheap
   f, available derivatives/closed forms, full-grid caching, or the enlarged
   input count can make it worse. Known-value integration can use the same
   envelope machinery. An all-method complexity lower bound is NOT claimed.
8. **Article gap.** Audit closest quantitative constructions, validate all law
   identities, implement charged exact arithmetic and show a useful COMPLETE
   operation against those controls for a real callback consumer. The paper
   2510.01941v2 is a close non-adaptive antecedent, not an unanswered generic
   existence problem. No priority, practical win, acceptance or fulfilled user
   goal is claimed from this initial proof/finite audit.
