# V7 whole-cost necessity screen, before competitive measurements

2026-10-17. V4/V5/V6 correctness is complete. This freezes a SMALL development
screen on ALL six original mathematical fixtures, not independently chosen
biological functions, a full genealogy or a positive paper result. The exact
functions/metadata are unchanged. No competitive times have been inspected.
Machine-readable cases, seeds, methods, budgets and gate:cost-protocol-v7.json.

The candidate has a plausible query/preparation advantage at rare higher
levels; the numerous cheap base votes, source work and persistent caches can
erase it. Formula-aware controls already need zero oracle queries; no known-
formula oracle lower bound is asserted. This screen resolves whether enough
whole-operation benefit remains to justify a separately frozen application.

Compare sparse with balanced dense, compact known-formula FD, its analytic-
derivative alternative and the equally informed lazy retrospective control.
For the four eligible polynomials ALSO include cheap non-adaptive padded and
output-only short-circuit factories. The latter is a legitimate comparator
for this output-only screen; it would need a different scope for ancestry-
before-colours. The two nonpolynomial splines have no claimed direct factory.

ALL value-based methods receive the fast original GMP piecewise callback
fromV5, not the slow independent Fraction audit function. Exact formula
access and analytic derivatives remain allowed to controls. No delay loops
or artificial expensive callback. Each cold draw creates its own factory and
three RNG streams inside the timer. A cached batch shares ONE factory and
advancing source/level/auxiliary streams, including its initial construction.
Sparse and lazy cache their deterministic state; dense/formula/derivative
also retain scalar results, compiled pieces and global grids/intervals.
No random outcomes are reused. Full source costs are charged even when a
control's chosen parent count is much smaller.

Modules and immutable supplied specification objects are loaded before API
timing, as for a resident numerical library. Factory construction, callback
arithmetic, levels, source/RNG, proposals/refinement, memory allocations and
the actual return list are measured. Do not time only query kernels. Also
record full child wall/CPU (imports/startup/serialization included) and peak
RSS from a fresh child per row. No subtraction of baseline memory or claiming
exact per-method GMP allocation from tracemalloc. Lab logging is not hidden
as zero consumer cost; total worker costs stay visible. There is no model,
tokenizer/training or biological clock to exclude in this operation.

One worker runs at a time on a fixed allowed CPU, with5 paired rotations.
Keep all1140 records, timeouts, resource failures, partial outputs and errors;
no favorable wins from incomplete controls. No integrity check/other workload
is deliberately run concurrently. Process resource guards are identical.
The uncapped mathematical factory is distinguished from this explicitly
capped screen; a RESOURCE_FAIL does not become a conditionally exact success.

A strong case win requires20% median paired API wall AND CPU improvement
against EVERY eligible control, with every paired repetition favorable.
The followup necessity gate is at least3/6 nonpolynomial cases in at least
one operation; report both operations and all polynomial losses. It is a
screen for a substantial reproducible signal, not a population significance
test, independent biological validation or sufficient novelty. If negative,
the current application ends without rescuing it by more seeds/degrees,
changing f/costs/thresholds or reporting only favorable conditional kernels.
Specific priority and the original user goal stay OPEN in either outcome.
