The reproducibility release is \href{https://github.com/j0taaa/tcc-final/tree/v0.1.1}{\texttt{j0taaa/tcc-final@v0.1.1}}; it contains the implementation audited at \href{https://github.com/j0taaa/tcc-final/commit/7b0d9aabeeaa3388b4b652b9e24d66f0da9b784d}{\texttt{7b0d9aa}}. The read-only EPIC submodule is pinned to \href{https://github.com/hyundong98/EPIC-Decoding/commit/5b1b31098f34ed3691d2a9f4aae14fdf5839d072}{\texttt{5b1b310}}, and measurement rows retain their own producing commits. The Python package contains independently readable reference solvers, proposal/support/lattice construction, orchestration, validation, the LLaDA adapter, and experiment code. The independent Rust 2021 crate \texttt{mwpc\_parser} implements the production max-plus CFG-on-acyclic-DAG dynamic program and backtracking; \texttt{mwpc\_parser\_py} is a thin PyO3 boundary. The integration exposes mutually exclusive \texttt{serial}, \texttt{epic}, and \texttt{exact} strategies and does not modify the baseline submodule.

% M20: detailed implementation contract retained from the main article.
The controlled Python normalizer computes nullable nonterminals, records start-symbol empty acceptance, removes $\varepsilon$ and unit productions, introduces terminal proxies, and right-binarizes longer rules while retaining source-production IDs. The parser boundary accepts only strict terminal/binary CNF plus that empty-string flag. Explicit graph $\varepsilon$-edges are normalized before parsing by maximum-weight acyclic closure; a returned path is expanded to original edge IDs. Thus $\varepsilon$ consumes no physical slot, and neither the Python nor Rust parser performs an implicit cyclic closure. The live structured tasks supply literal UTF-8 byte CFGs directly, so the production path uses no lexical transducer.

For the pinned LLaDA tokenizer, every ordinary base-token piece is mapped compositionally to raw bytes by reversing the GPT-2 ByteLevel bijection; singleton calls to \texttt{decode} are not used to construct lattice emissions. The 126,080 base IDs are ordinary byte-emitting tokens, whereas all 269 added IDs are unsupported as content. The live adapter ranks the maximum needed support once on-device by logit descending and token ID ascending. Each masked row represents its current top-$K$ prefix, the frozen proposal token, and required termination/PAD IDs; fixed rows are singletons. Historical Q5 used $K=8$ and feasibility-driven doubling to 16 and 32, stopping at the first feasible support. Every optimum is therefore reported as \texttt{exact\_on\_support} for the current finite canvas and step, never as a full-vocabulary or future-trajectory optimum.

At each step, the baseline schedule ranks eligible masked positions by primary-token confidence descending and absolute position ascending, retains at most its budget, and creates one frozen primary proposal per position. The live studies use the model softmax confidence itself as the non-negative proposal weight; non-proposal alternatives have zero reward. Equal MWPC scores use stable implementation traversal only---there is no claimed secondary objective. The required EOS profile accepts IDs 126081 and 126348 as the first termination event and uses 126081 as canonical PAD afterward; all specials consume physical slots but emit no CFG byte. The historical adaptive Rust deadline was 30 seconds total, with remaining time passed to each attempt, and \texttt{TIMEOUT} remains distinct from support infeasibility. An optimal zero-match witness advances at the eligible position whose witness token has highest model probability. The reported Q5 exact configuration has no non-optimal fallback; the generic adapter can invoke an explicitly configured serial or EPIC callback while retaining the original solver status and without assigning an exact guarantee to that update.

The corrected nonliteral study uses the same \texttt{GSAI-ML/LLaDA-8B-Instruct} checkpoint on an RTX 3080 Ti, quantized with NF4. Twelve pilot prompts and twelve disjoint confirmation prompts cover balanced brackets, parenthesized arithmetic and nested JSON arrays. Each family has one recursive byte grammar shared across prompts, rather than a literal target grammar. Independent checkers distinguish syntactic validity from bracket counts/depth, arithmetic value and leaf multiset, or ordered JSON leaves/depth. All strategies receive 32 slots, 16 steps and two initial transfer proposals per step. The exact support starts at $K=2$ and expands to 4 and 8 with a five-second solver budget; a supervisor also limits generation to 60 seconds. Two warm-up forwards precede each measured shape, CUDA timing is synchronized, strategy order rotates, and model loading is excluded. Confirmation uses two repetitions per task, which are repeated measurements rather than additional tasks. Fixed steps can leave an incomplete canvas after rejected proposals; such outcomes remain in the denominator.

The five questions cover oracle agreement (Q1), heuristic loss (Q2), finite-slot false positives (Q3), scaling (Q4), and end-to-end decoding (Q5), against brute force, serial, EPIC/heuristic, and unconstrained baselines where applicable. Q2 reports $\Delta_H=W(J^*)-W(J_H)$ and $\delta_H=\Delta_H/W(J^*)$ when $W(J^*)>0$; Q4/Q5 record validity, batches, fallbacks, runtime, RAM/VRAM, and component timings on common hardware. Automated tests independently check grammar acceptance, proposal/objective reconstruction, fixed positions, EOS/PAD slots, and brute-force agreement. Locked dependencies, configs, raw results, and generators complete the reproduction path.

The recursive scaling study varies 16--128 slots, widths 2/4/8 and fixed nesting depths 0/4, with three repetitions per setting. Across \MReviewScalingCases{} executions, \MReviewScalingTimeouts{} reached the one-second native limit; every completed optimum passed independent syntax validation. Graphs reached \MReviewScalingMaxNodes{} nodes and \MReviewScalingMaxEdges{} edges, with maximum observed process RSS of \MReviewScalingMaxMiB{} MiB. The timeouts occurred at the largest width/slot settings. This extends the earlier small envelope and identifies a time limit within the tested range; it does not establish a universal memory bound. Width also changes token byte length, so its effects cannot be isolated.

In the corrected pilot, exact completed 1/12 generations and had no functional successes; serial and EPIC each completed 7/12 and succeeded on 3/12. The first pilot's 18 observation errors were retained separately and corrected before confirmation. No task, budget or success criterion was tuned in response. Table~\ref{tab:review-live} reports the disjoint confirmation: exact completed the bracket outputs, but all failed the requested counts/depth; arithmetic and JSON remained incomplete. Serial and EPIC achieved functional success only on one JSON task, repeated twice. Syntax preservation at accepted steps therefore did not ensure completion or task success within this budget. Runtime comparisons must be read together with these failure counts; the study establishes no end-to-end advantage for exact selection.

The tokenizer contract is the pinned raw ByteLevel byte stream, not singleton-\texttt{decode} Unicode. Added controls are content-unsupported except EOS/PAD; the live path has no programming-language lexer semantics (maximal munch, priority, or context) in the optimizer. Separate task checkers assess functional output. A CFG constrains syntax only, not types, references, execution, or tests. Independent checks mitigate error, but evidence covers one quantized checkpoint and one host. The pilot and confirmation have only twelve tasks each; repetitions do not enlarge those samples. Most nonliteral outputs fail the functional checks. EOS/PAD rewards also make proposal counts an imperfect measure of useful content. The greedy comparator still rebuilds charts for unmatched proposals; incremental Boolean parsing remains untested. These limits prevent a general practical-superiority claim. The historical literal-task runtime ratios additionally confound the selection rule with unequal proposal budgets.
