\subsection{Certified JSON repair}

For a draft $d$, create one proposal $(i,d_i,w_i)$ per slot. The identity
$R_C(y)+\sum_i w_i\indic[y_i\ne d_i]=\sum_iw_i$ makes MWPC minimize weighted token substitutions. Byte intervals protect every intersecting token. This is a bounded application of scored parsing, not a new language-edit-distance algorithm \cite{kociumaka2024edit}. The implemented support swaps container kind or comma/colon outside strings, retaining only represented same-length byte alternatives. It performs no insertion/deletion and claims only \texttt{exact\_on\_support}.

The study corrupts fictional records with an integer ID and arrays of integer pairs. A shared schema fixes keys, order and types, never answers. Four pilot documents have one/two records; twenty confirmation documents have three/four records and two timing repetitions. Each yields valid, opening/closing/separator-swap, missing-suffix and wrong-value cases. Bytes and the pinned LLaDA tokenizer are separate profiles, without inference. Eight further documents use an ambiguous JSON CFG.

Comparators include unchanged input, \texttt{json\_repair} 0.63.5 with default and schema standard/salvage modes \cite{baccianella2025jsonrepair}, increasing-edit enumeration, unweighted CFG completion and witness-reusing greedy. Schema-guided tools retain the stronger schema in the ambiguous cohort. Independent checks require original values and structure. Each worker has two seconds and 2 GiB; timings include construction and exclude one-time loading. \label{alg:step}
\small
\footnotesize
\begin{algorithmic}[1]

\Ensure new state $x'$ with completion feasibility preserved, or an infeasibility diagnostic

  \EndIf
\EndIf

\end{algorithmic}

\subsection{Optional lexical composition}
Conceptually,
\begin{equation}
A_{\mathrm{lex}}=(A_{\mathrm{tok}}\cap A_H)\circ T_{\mathrm{detok}}\circ T_{\mathrm{lex}}.
\end{equation}
$T_{\mathrm{detok}}$ maps tokens to bytes, $T_{\mathrm{lex}}$ maps bytes to lexemes, and $A_H$ implements EOS/PAD over token IDs. The synchronized product precedes detokenization so its operands read the same alphabet. Token-arc weights and provenance survive composition. The relation must reflect maximal munch and priorities: accepting arbitrary segmentations can accept a sequence a real lexer would reject. No such programming-language lexer is integrated into the live production path.
