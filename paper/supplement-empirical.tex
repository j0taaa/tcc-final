\section{Implementation and Evaluation Methodology}
\label{sec:metodologia}

EPIC remains read-only at \texttt{5b1b310}; \texttt{serial}, \texttt{epic} and \texttt{exact} remain available. Python implements the readable reference, support construction and independent validation; Rust implements the production parser through thin PyO3 bindings. Parent software and research artifacts use MIT; manuscript rights and upstream notices remain separate. Every measured cohort records its source commit, immutable configuration, seed, grammar/support hashes, model/tokenizer revisions, hardware and statuses. Full traces and generating scripts are versioned separately from derived tables.

The historical local submission release \texttt{v0.2.0} remains available; subsequent studies retain their own producing commits.

Normalization produces strict CNF and an empty-word flag; epsilon closure retains original paths. The LLaDA tokenizer reverses ByteLevel pieces to compositional bytes, including split UTF-8 characters. EOS/PAD consumes physical slots without emitting bytes. Fixed rows are singletons; independent checks validate witness acceptance, provenance, selected proposals and recomputed score. Python rational sums and Rust integer-scaled sums compare binary64 weights without intermediate-rounding order changes; the public score remains a float. Arithmetic-operation bounds do not imply constant bit cost. Detailed contracts and historical configurations remain in \path{paper/supplement-method.tex}.

\subsection{Correctness, selection quality and scaling}

Exhaustive completion/subset oracles compare the Python and Rust objectives, allowing different optimal witnesses. Tests cover duplicate proposals, invalid weights, finite-slot counterexamples, empty outputs, fixed positions, timeouts and byte provenance. Recursive synthetic configurations measure possible heuristic loss; saved real-model states compare selectors on identical logits, canvases and supports. Runtime replays aggregate repetitions within each state. Their score and selector-time results are distinguished from end-to-end task success.

The recursive generation study uses twelve development and twelve disjoint confirmation prompts for brackets, arithmetic and JSON, with 32 slots and matched initial proposal budgets. Its incomplete and incorrect outputs remain failures. Controlled minimum-substitution JSON repair is a separate model-free application: one proposal per original token minimizes represented substitutions while preserving protected spans. Its full protocol, positive and negative classes, and library/enumeration controls remain in the supplement; tokenizer use alone is not dLLM inference.

\subsection{Live commitment-policy comparison}

All new live studies use \texttt{GSAI-ML/LLaDA-8B-Instruct}, revision \texttt{08b83a6}, NF4 double quantization with bfloat16 compute, on an RTX 3080 Ti and one CPU thread. Two warm-ups precede measurement. CUDA is synchronized; loading is excluded and support/grammar preparation plus EPIC's official recovery are included. Method order rotates by request and is reversed in the second confirmation execution. Model forward, candidate construction, support construction, selection and update times are separately recorded. Repetitions measure timing stability, not additional independent tasks.

The synthetic tool study translates requests to nested calculator calls without evaluating away requested operations. Thirty requests develop policies; 100 new requests from the same templates form confirmation. A fixed call grammar and question-derived operand filter never read the expected call. Each method receives 24 canvas slots and at most 24 model forwards. MWPC takes the highest-probability allowed proposal at each free position, with weights normalized over the model's full vocabulary. Budget policies restrict this proposal set before solving. Confidence policies keep the optimizer's full certificate but commit only matched tokens above threshold $\tau$, falling back to one matched proposal or a witness token to make progress.

Controls include confidence-greedy selection with witness reuse, actual upstream EPIC with several reveal schedules, and canonical-catalog mean-field MAP using sums of token log probabilities. MAP maximizes a different objective and is explicitly limited to canonical token paths; the byte CFG can accept other represented tokenizations. EPIC uses its native vocabulary, lexical whitespace and abstract gaps, so it is a system comparison rather than an identical-support optimality comparison. A matched greedy/exact comparison isolates selection under shared supports.

The frozen primary comparison is MWPC with $\tau=0.8$ versus EPIC with 24 steps. We report paired correctness differences, a conservative 95\% interval from exact win/loss binomial intervals, exact McNemar tests and paired latency ratios with 2,000 request-level bootstrap resamples. Secondary policy/schedule comparisons have no multiplicity adjustment. Strict grading preserves the requested syntax tree; a declared sensitivity check removes lexical layout differences while preserving quoted string contents. Numeric equivalence is reported separately.

\subsection{External grounded calls and practical dispatch}

Eight enum-only BFCL cases were too narrow to support external generalization. The extension audits 658 public records at pinned Gorilla revision \texttt{6ea5797} \cite{bfcldataset}. Eligibility uses schemas only: one query-named function, one to three scalar arguments and exactly one unrestricted string field. All 68 eligible cases are retained. Hash-ordering function-name families assigns 26 requests from eight families to development and 42 requests from 42 other families to confirmation; this does not guarantee unrelated semantic domains.

The free field receives at most 96 deterministic candidates from quoted/capitalized spans and contiguous question spans up to six words, plus schema defaults. Numeric values come from the request or defaults, with a declared 0--10 fallback; enums and optional omissions follow the schema. The cap is 4,096 canonical calls and 64 slots. All 68 catalogs fit, with at most 43 ordinary tokens. Only after construction, an independent coverage audit finds acceptable answers in 56 of the 68 supports; the other twelve remain evaluation failures. A strict scalar AST checker evaluates original schemas and public acceptable values. This is not the official BFCL score or unrestricted argument generation.

The protocol retains strong EPIC schedules, matched greedy and iterative/one-pass MAP controls, at most 64 forwards, 120 seconds per generation and ten seconds per selection. A local demonstration uses the same decoder to produce a geographic lookup, validates the AST and dispatches only a read-only Open-Meteo query \cite{openmeteogeocoding}. Live inference and archived replay are explicit modes. Such a runnable flow establishes integration, not population accuracy or a need for an LLM in geocoding itself.

Paired greedy/exact median time ratios are \MAuditTwoMin{}--\MAuditTwoMax{}, \MAuditEightMin{}--\MAuditEightMax{} and \MAuditAllMin{}--\MAuditAllMax{}, respectively; budget 2 does not benefit. A bracket state improves ordinary matches from seven to eight alongside 23 EOS/PAD matches. No replay witness passes the functional checker.

Recursive scaling spans 16--128 slots and widths 2/4/8. Of \MReviewScalingCases{} runs, \MReviewScalingTimeouts{} reach the native one-second limit; completed optima pass validation. Maximum observed RSS is \MReviewScalingMaxMiB{} MiB, not a universal bound. In the matched-budget recursive live experiment, the study establishes no end-to-end advantage: exact completes brackets but misses requested counts/depth, while arithmetic and JSON stay incomplete. Serial/EPIC succeed only on one confirmation JSON request.

Historical Q2 gaps are illustrative, not typical-model estimates: singleton snapshots cannot estimate a representative gap. These artifacts and full negative results remain in the supplement.
