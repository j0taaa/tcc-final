\section{Exact Recursive-Grammar Posterior Compilation}
\label{sec:cfg-posterior}

The principal backend compiles Equation~\ref{eq:represented-posterior}.
It computes $Z_S$, original-token marginals and exact samples without enumerating
valid sequences or every parser-stack configuration. Weighted CFG sampling is
established: Rivaud and Pachet already prove tractability for unambiguous
CFG/Markov constraints \cite{rivaud2017sampling}. Our contribution is its checked,
reusable finite-token interface for frozen dLLM predictions, including subword
aliases, physical positions and explicit support loss. It is not a new
sum-product parsing principle or a claim of scientific priority.

\begin{theorem}[Finite-token posterior]
Assume a checked LL(1) byte source grammar, nonempty compositional ordinary-token
emissions, absent EOS, $n$ physical slots and nonnegative rational unaries.
The compiled forest computes $Z_S$ and all token marginals exactly. If $Z_S>0$,
its integer categorical sampler returns each original sequence $y$ with
probability $P_S(y)$, preserving every fixed position and consuming exactly $n$
tokens. With $v$ token-DAG vertices, $e$ edges, $h$ nonterminals and $r$ binary
rules, forest construction uses at most $O(rv^3+eh)$ arithmetic alternatives and
$O(hv^2)$ chart cells; subsequent evaluation is linear in forest size.
\label{thm:cfg-posterior}
\end{theorem}
\begin{proof}
Private proper-prefix sharing closes each token on its own last-byte edge.
Every complete DAG path consequently chooses exactly one original token per
slot. Prefix tokens can close or continue; byte aliases remain distinct weighted
closures. FIRST/FOLLOW disjointness and absence of nullable left recursion
certify unique source parses. Private binarization, nullable and unit elimination
lift normalized trees to source trees, so a token path is counted once.
Inside induction on topological span sums precisely the accepted path weights.
Reverse differentiation attributes each path to its one closure in each slot,
giving token masses and marginals after division by $Z_S$. Sampling alternatives
proportional to their inside contributions telescopes to $q(y)/Z_S$.
Each binary rule can join at most $v^3$ endpoint triples; terminal alternatives
contribute at most $eh$. Bit cost of exact integers is additional to this
arithmetic-work bound; cubic parsing need not be cheap.
\end{proof}
These bounds concern the finite DAG/normalized grammar after validation;
source normalization and comparison to the supplied input have separate costs.
Canonical comparison retains its exact structural contract but may expand
exponentially; a shared work cap refuses projected expansion before allocation.
Stable deduplication removes identical nullable bodies without changing their
first-occurrence order or resulting production provenance.
For the fixed JSON grammars below, that source cost is independent of depth.

\paragraph{Exact arithmetic and reuse.}
For row denominators $d_i$, set $a_i(t)=d_iq_i(t)$ and $D=\prod_i d_i$.
Every complete path has integer weight $Dq(y)$, hence root mass $DZ_S$.
The factor $D$ cancels from marginals and categorical sampling; retained rows
are never silently renormalized. Binarizing long source bodies \emph{before}
nullable expansion preserves trees and avoids exponential optional-subset
expansion of those bodies. When subsequent steps reweight, remove alternatives
or commit previously free positions, zero the removed original-token choices
and reuse the same forest. This exactly restricts its path sum. Expansion or
undoing an existing commitment requires recompilation. Committing any subset
of a returned full witness preserves finite-support feasibility; applying a
fixed update map preserves the corresponding posterior pushforward. Neither
fact proves the neural model's complete denoising distribution correct.

\paragraph{Mathematical reason to use this representation.}
Two-type balanced delimiters have $2^d$ opening stacks of length $d$, each with
its unique reversed closing suffix. Matching pairs concatenate to a valid word;
crossed pairs do not. An accepting NFA run for each pair must therefore visit
a distinct midpoint state, implying at least $2^d$ states even for this
finite-length slice. A fixed LL(1) grammar and the preceding polynomial forest
avoid this explicit sequential-state expansion. This is the classical
fooling-set argument specialized to the interface, not a lower bound for all
factor graphs or specialized algorithms. Lean checks finite distinctness/counting,
the conditional state bound and row-product scaling; the full sampling law,
normalizer and Python implementation are not mechanized source refinements.

The separation applies to genuine JSON forms: choose each of $d$ opening tokens
from \texttt{[} and \texttt{\{"x":}, fix the middle token to \texttt{0}, and choose
each closing from \texttt{]} and \texttt{\}}. Every opening sequence has exactly
one valid closing sequence, so the $2^{2d}$ represented sequences contain
$2^d$ valid documents. Under uniform row choices, $Z_S=2^{-d}$ and independent
rejection needs $2^d$ trials in expectation. A fixed LL(1) grammar recognizes
these recursive JSON forms; our token DAG has $O(d)$ vertices and polynomial
inference work. This is a mathematical family, not a model benchmark or a
new discovery of grammar-sampling tractability. Specialized CFG algorithms
can achieve this advantage too.

Exact arithmetic does not hide an exponential bit requirement here. If $b$
is the total bit length of input denominators, then $\log_2 D\leq b$. A span
path contains at most $v-1$ byte edges and one closure per encountered slot,
with each integer closure weight at most its row denominator. Strict-CNF trees
over those edges have $O(v)$ nodes; their shapes, rules and edge choices number
at most $(4(e+r+h+1))^{O(v)}$. Inside and outside integers thus need at most
$b+O(v\log(e+r+h+1))$ bits. Together with the polynomial forest bound, standard
integer arithmetic gives polynomial inference bit work, while constants and memory can
still make compilation impractical.

\paragraph{Useful capability and competing methods.}
The use is a probabilistic backend for recursive JSON/DSL generation and
multi-region infilling: obtain a valid completion and its original-token
marginals without repeated independent guessing or repair-induced distortion.
EPIC optimizes practical CFG-constrained decoding, not this exact posterior.
LAVE samples lookahead prefixes and explicitly allows rejecting extendable
proposals \cite{zhang2026lave}; it does not compute $Z_S$ or this joint law.
Exact automaton conditioning \cite{dang2026automata} explicitly excludes CFGs;
FactorDLM \cite{su2026factor} is an exact-inference alternative whose cost depends
on its factor encoding. We claim neither general speed superiority over these
decoders nor that all factor encodings suffer the stated automaton bound.
